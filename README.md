# AgroBalance

Веб-приложение для планирования орошения: участки, погода, расчёт водного баланса, календарь, журнал поливов и аналитика. Интерфейс на русском, адаптивный от 360 px.

**Стек:** React, TypeScript, Tailwind CSS, Recharts; FastAPI, SQLAlchemy, Alembic; PostgreSQL; Docker Compose.

## Быстрый запуск через Docker

Установите и запустите Docker Desktop с поддержкой Linux-контейнеров. Из корня проекта:

```powershell
python scripts/configure.py
docker compose up --build -d
```

Откройте http://localhost:8000. Нажмите **«Открыть демо-хозяйство»** — появится отдельный тестовый аккаунт с тремя участками, учебной погодой и историей поливов. Личные аккаунты создаются кнопкой «Создать аккаунт». Для них доступна реальная погода и ручной ввод ETo.

OpenAPI: http://localhost:8000/docs · JSON: http://localhost:8000/openapi.json · здоровье: http://localhost:8000/api/health.

Остановка с сохранением данных: `docker compose down`. Логи: `docker compose logs -f app`. Не используйте `down -v`, если нужно сохранить базу.

## Локальный запуск без Docker

Нужны Python 3.12 и Node.js 22 с npm. PostgreSQL необязателен для локального демо: по умолчанию используется SQLite-файл `agrobalance.db` в корне. Локальная БД не является заменой целевой проверки PostgreSQL.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
cd frontend
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm run build
cd ..
.\start-local.ps1
```

Если запуск PowerShell-скриптов ограничен политикой компьютера, выполните напрямую:

```powershell
.\.venv\Scripts\python.exe -m alembic -c backend/alembic.ini upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

В текущей рабочей копии окружение `.venv` и собранный frontend уже подготовлены. Повторно устанавливать зависимости не требуется.

### Разработка frontend

Запустите backend командой выше. В отдельном терминале: `cd frontend`, затем `pnpm dev`. Откройте http://localhost:5173. Vite проксирует `/api` на backend; cross-origin доступ к cookie не нужен.

## Настройки

Скопируйте `.env.example` в `.env` либо используйте `scripts/configure.py`, который генерирует случайный пароль БД и не перезаписывает файл.

| Переменная | Назначение |
|---|---|
| POSTGRES_PASSWORD | Случайный URL-safe пароль БД для Docker |
| DATABASE_URL | Необязательное подключение для локального backend; Docker задаёт своё |
| APP_PORT | Локальный порт Docker, по умолчанию 8000 |
| COOKIE_SECURE | true только при HTTPS |
| ALLOWED_ORIGINS | Точные разрешённые адреса интерфейса через запятую |
| ENABLE_DEMO | Включение создания учебных аккаунтов |
| DOMAIN | Домен Caddy для публичного HTTPS |

Секреты храните только в `.env`/окружении. Погодный API в демонстрационном некоммерческом использовании работает без ключа; условия использования необходимо проверить для реального запуска.

## Демонстрационный сценарий

1. Войти кнопкой демо; открыть «Северное поле» (кукуруза, 1 га).
2. Начальный дефицит 39 мм, TAW 100 мм, p 0,4, эффективность 0,8, целевой дефицит 12 мм.
3. Ввести ETo `3.3333333333333335` и эффективные осадки `2` на сегодняшнюю дату. При Kc 1,2 получим ETc 4 мм.
4. Результат: дефицит 41 мм, RAW 40 мм, чистая норма 29 мм, валовая 36,25 мм, объём 362,5 м³.
5. Добавить выполненный полив на 362,5 м³. Дефицит станет 12 мм; оставшаяся рекомендуемая норма — 0.
6. Повторить расчёт: вода повторно не спишется. Исправление или удаление записи восстановит корректный баланс.
7. Проверить календарь и аналитику. Для создания своего участка заполнить параметры, дату посадки и начало баланса; для каждого дня от начала баланса нужны ETo и Pe.

Дата посадки в демо автоматически выбирается так, чтобы культуры были в середине сезона. Тестовая погода и история явно отделены от реальных данных и не зависят от интернета.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -c backend/pytest.ini backend/tests -q
cd frontend
pnpm run build
```

Проверяются контрольная математика, границы и неверные значения, регистрация/вход/смена пароля, права доступа, блокировка cross-site запросов, лимит входа, повторный расчёт, дублирование и исправление полива, пропуски дней, отделение прогноза, недоступность погоды и OpenAPI. База каждого API-теста изолирована в памяти.

## Публичный сервер и HTTPS

На сервере с Docker направьте DNS домена на его IP, откройте 80/443. В `.env` задайте `DOMAIN=ваш.домен`, `COOKIE_SECURE=true`, `ALLOWED_ORIGINS=https://ваш.домен`. При необходимости отключите учебные аккаунты через `ENABLE_DEMO=false`.

```sh
docker compose --profile public up --build -d
```

Caddy получает сертификат и направляет запросы к API. Порт PostgreSQL наружу не публикуется; порт приложения привязан к loopback. Настройте резервное копирование и проверьте восстановление до работы с реальными данными.

### Резервная копия

```powershell
python scripts/backup.py
```

Файл custom-format появится в `backups/`. Запускайте ежедневно через планировщик ОС и храните копию вне сервера. Для восстановления сначала создайте отдельную тестовую БД, затем:

```sh
docker compose cp backups/ИМЯ_КОПИИ.dump db:/tmp/agrobalance.dump
docker compose exec db createdb -U agrobalance agrobalance_restore
docker compose exec db pg_restore -U agrobalance -d agrobalance_restore --no-owner /tmp/agrobalance.dump
```

Это восстанавливает отдельную базу и не перезаписывает рабочую. Переключение приложения на восстановленную БД выполняется оператором после проверки.

## Структура и границы

- `backend/app`: API, безопасность, модели, расчёт и сервисы.
- `backend/migrations`: версионируемая схема БД.
- `backend/tests`: автоматизированные проверки.
- `frontend/src`: интерфейс, типы данных и API-клиент.
- `docs/ARCHITECTURE.md`: формулы, источники, архитектура и ограничения.
- `docs/VERIFICATION.md`: результаты проверок текущей версии.

Модель рекомендательная; TAW, p, Kc и Pe требуют агрономической проверки. Гарантии экономии воды не заявляются. Управление оборудованием, IoT, ML, восстановление пароля, экспорт и полноценная многоязычность — последующие этапы. Публичная демонстрация требует сервера; исходный проект и локальная версия не зависят от облачного аккаунта.
